# 任务模式与完成标准

规则来源：任务范围遵循 [SKILL.md](../SKILL.md)；章节、数量和策略结构遵循 [report-structure.md](report-structure.md)；证据遵循 [evidence-quality.md](evidence-quality.md)。排版不改变研究范围。
## 选择顺序

先看用户要交付什么，再看资料有哪些。任务书提供研究依据，不自动扩大任务范围。
新项目首先按 SKILL.md 确认课程设计/实际项目/竞赛作品；这与下列任务模式是两个独立维度。
类型侧重与阶段深度遵循 [project-types.md](project-types.md)，在各模式范围内应用，不另设权重或扩大任务。
各模式的主文档均由用户选择 Obsidian、飞书或 DOCX，
主文档交付后才进入 HTML 演示选择；不以文件格式决定研究模式。
用户明确“只做案例库”时选择案例库；“补充现有案例库”采用研究补充模式，并加载案例匹配规则。
混合请求可以组合模式，说明组合范围；例如完整调研附案例库。不要同时套用多套完整模板。

## 完整前期调研

- 输入：任务书、场地资料及用户指定参考。
- 流程：项目理解 → 相关场地/环境/人群/功能研究 → 问题与机会 → 案例 → 备选方向及分析计划 → 策略。
- 九模块是组织模板；分析深度由设计问题和资料决定。指标缺失时明确限制，不为填版面补造内容。
- 完成：任务书要求和主要问题有对应证据；策略说明具体空间动作、参考案例与适用条件；来源可追溯。
- 研究重点、案例阅读和方向验证体现 project-types.md 中有关要求；完成程度同时符合当前阶段，未做验证保留为计划。
- 设计转译按 [design-directions.md](design-directions.md)：给出数个不同的可能方向，每个说明重点问题、
  要补的分析、建议成果及其如何影响设计选择；不把拟开展分析标成已完成。

## 专题研究

- 输入：明确问题，如街巷边界、人群活动、气候响应、历史建筑再用。
- 流程：界定问题与尺度 → 取证 → 分析 → 空间启示 → 待核实事项。
- 完成：回答专题问题，说明证据和适用边界；不另做无关的气候、体量或完整报告。
- 用户要求备选方向时按 design-directions.md 在专题范围内生成；不默认扩成完整项目策划。
- 示例：“只帮我研究老人活动与社区公共空间”应围绕行为、使用时段、可达性与空间关系展开。

## 案例库建设

- 先读任务书与已有案例，提取共同特点及各案例独特特点，建立匹配维度。
- 按指定地区、数量和主题搜索；数量未指定时，选择覆盖关键维度的有限集合，说明范围。
- 使用 `precedent-matching.md` 核验与分类；不能只按知名度或建筑类型入选。
- 新案例检索遵循其中的经典大师、近年资料丰富同类型、其他专项参考顺序；经典数量计入总数，已有库先补缺口。
- 内容：单案记录 + 总索引 + 比较矩阵；按任务需要增加设计转译说明。
  Obsidian 可用独立笔记，飞书/DOCX 可用相应章节或表格；文件形态遵循用户所选主文档形式。
- 已有框架（如 Site / Place / Scene）优先沿用；保留原有案例，说明新增和既有数量。
- 完成：每个案例有可核实来源、入选理由、可学习动作、差异和迁移条件；索引与文内链接有效。
- 不要求本地气候、规划、体量分析或固定数量的完整策略卡，除非用户同时要求。

## 已有研究补充

- 先读取现有文档，列出用户要求修改的部分和证据缺口。
- 保留格式、命名、分析框架和已有结论；新证据推翻结论时说明依据并修订受影响部分。
- 只更新必要文档、比较表、索引和链接；不重新生成整套研究。
- 补充案例时继续执行匹配规则；补充气候时只加载相关气候资料。
- 完成：新增信息填补指定缺口；相关对照与链接同步；明确哪些信息仍未核实。

## 关键歧义与可继续的缺项

| 情况 | 处理 |
|---|---|
| 两份任务书对应不同项目，用户未指明研究哪一份 | 提问，先做可独立的资料盘点 |
| 已确认 Markdown，后来进入渲染阶段 | 直接交付 Markdown，不重复询问 |
| 没有最终地块面积，但只要求类似案例库 | 标注待定，继续案例研究 |
| 用户说“所有案例不要文件夹，直接 .md” | 同一案例目录放独立文档，不建每案例子目录 |
| 用户指定 DOCX 作为课程提交格式 | 按已选 DOCX 交付，交付后询问 HTML 演示需求，不重复询问主文档形式 |
| 用户只要求界面改造案例，已有资料还有交通和气候 | 仅调用与界面问题有关的信息 |

完成范围由用户目标决定；默认模板只补足组织方式，不扩大授权任务。
