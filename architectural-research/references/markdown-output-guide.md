# Markdown 交付规则

规则来源：任务范围遵循 [SKILL.md](../SKILL.md)；章节、数量和策略结构遵循 [report-structure.md](report-structure.md)；证据遵循 [evidence-quality.md](evidence-quality.md)。排版不改变研究范围。
仅在用户选择 Obsidian/Markdown 档案或明确更新已有 Markdown 时加载；此格式不是默认主文档。
用户选择飞书或 DOCX 时，内部 Markdown 草稿不作为另行要求的 Obsidian 交付。
## 格式与文件组织

先执行用户已确认的格式与组织要求，再沿用已有资料习惯。
若尚无结构，案例库默认在同一案例目录放独立 `.md` 文档，不为每个案例创建子目录。
全新目录的路径优先采用用户指定位置，否则放当前项目下的“案例”。保留原有文件，避免同名覆盖。
图片仅在需要且允许本地素材时共用一个素材目录；用户要求只有文档时使用已核验远程图链或来源页链接。
Markdown 中图解与真实项目图分开标明；不能用示意图充当测绘成果。

## 案例库默认交付

- `00_案例库索引.md`：范围、选取依据、既有/新增数量、按地区或参考方向组织的案例链接。
- `01_案例比较矩阵.md`：使用本任务共享维度对照，区分核心对标与专项补充。
- `<案例名称>.md`：每个项目一篇，可沿用已有命名方式。
- 按需要增加设计转译或来源目录；不强制制造用户未要求的附属文档。
- 新索引/比较表沿用 precedent-matching.md 的三类顺序，标注建成时间和可用资料；类别与核心/专项参考作用分开。
  保留已有组织，不为三类另建用户未要求的文件夹。

### 单案例结构

已有模板或分析框架优先。没有模板时使用：

1. 基本信息：名称、地点、设计者、时间、面积及其口径、来源。
2. 入选理由：对应的原案例/任务书问题、匹配维度及参考等级。
3. 场地、人群、矛盾和主要空间动作。
4. 实施与运营条件；未披露的信息注明。
5. 对当前任务的转译：可学习动作、前提、不可直接复制的部分。
6. 图像、图纸与读图说明；按现有图片规则与用户格式处理。
7. 来源与待核实问题。

用户已有 Site / Place / Scene 等框架时，沿用这些章节表达上述要点，不额外叠加一套重复模板。

## 专题、完整调研与更新

- 专题：问题 → 证据 → 分析 → 空间启示 → 限制与下一步。
- 完整调研：交付可在 Obsidian 中持续维护的项目档案，内容覆盖 report-structure.md 的相关研究成果；
  报告结构不等于文件结构，不机械地一章一个文件；不引入 HTML/CSS 组件或占位代码。
- 更新：在原文结构中修订，并同步受影响的索引和比较矩阵；不重复生成整库。
- 筛选、候选入库和位置纠正的同步范围遵循[research-maintenance.md](research-maintenance.md)，修改前及交付前核对真实文件清单。

### 用户选择 Obsidian 时：已认可形式与待定结构

- 用户已有案例库可包含总索引、独立案例笔记、
  比较矩阵、课程设计转译、研究口径与来源目录。这是组织参考，不是所有项目的固定输出位置。
- 新完整调研应形成详细、系统、可补充复用的档案；总览可导航到各笔记，笔记与来源、案例及设计判断相互关联。
- 沿用目标知识库的文件命名、属性、标签和链接习惯；所需图片/图纸保留图注、来源与证据状态。
  优先使用不依赖额外插件也可阅读的 Markdown，不自行安装插件或改动 Obsidian 配置。
- 具体分区、文件粒度、属性字段、附件组织，以及项目档案与共享案例库的关系尚未确认，留待与用户讨论。
  现有案例库的组成是参考，不代表完整调研档案的目录已确定；不新增一套强制分类。
- 写入位置采用用户指定或本项目已确认路径，不因旧样例位于知识库而把新项目自动写入该路径。
  生成档案与直接写入既有库分开说明，遵循用户授权和环境权限；已有笔记保留并按需增量更新。
- 主文档交付后按 SKILL.md 询问 HTML 演示需求；需要时引用同一研究结论与来源记录，不重复展开研究。
- 完整研究包含 design-directions.md 规定的备选方向与后续分析计划；将方向关联到发现、案例、策略和分析成果，
  暂不规定单方向单文件、额外目录或新属性体系；后续分析未执行时保留为计划。

## 交付检查

- 所有 `.md` 保存为 UTF-8；表格列数一致，列表前留空行。
- 文档之间使用相对 Markdown 链接；面向用户的交付消息使用可点击绝对路径。
- 检查本地文档/图片链接，尤其是移动或改名之后。
- 外部来源沿用 evidence-quality.md 核验规则；链接必须支持关联信息。
- 数量与索引一致，不将同一个案例的不同页面重复计数。
- 可按需运行`scripts/check_library.py`做只读检查；分类与排除项先匹配当前库，不把工具通过说成研究或外部来源通过。
- 简要告知文件位置、完成范围和影响使用的资料缺口。
